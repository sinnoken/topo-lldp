## ## 運作原理 (How It Works)

此程式模擬了一個簡易的路由交換引擎，透過以下四個步驟實現路徑追蹤：

### 1. **路由表建模與 CIDR 解析**

程式會解析使用者輸入的各設備路由資料（如 Juniper 的 `show route` 或 Cisco 的 `show ip route`）：

* **網段識別**：利用正則表達式提取目標網段（Destination）與下一跳（Next-hop）。
* **最長匹配優先 (LPM)**：當查詢特定 IP 時，程式會模擬路由器行為，在路由表中尋找掩碼最長（最精確）的路由條目。

### 2. **遞迴路徑追蹤 (Recursive Path Tracing)**

這是該程式邏輯最精彩的部分。當使用者啟動「分析」時：

* **跳轉模擬**：程式從指定的「起點設備」開始，根據路由表找到下一個節點。
* **路徑封裝**：它會不斷遞迴（Recursive）直到滿足以下條件之一：抵達目的地、發生環路（Loop）、或找不到路徑（Blackhole）。
* **支援 ECMP**：如果一筆路由有多個等價的 Next-hop，程式能同時記錄這些分支。

### 3. **視覺化狀態標記**

程式會將分析結果回饋給 `vis.js` 渲染引擎：

* **動態高亮**：分析出的路徑會被標記為特定顏色（如綠色或動態流光），與背景的靜態拓樸區隔開來。
* **節點標註**：在路徑經過的節點旁顯示該節點轉發此封包時所依據的具體路由條目。

### 4. **資料持續化與快取**

* **Storage 整合**：分析過的路徑結果會存儲於 `localStorage`，避免重複執行複雜的運算。
* **過期機制**：與拓樸資料同步，確保路由表過時後會自動提醒使用者更新。

## ## 應用場景 (Use Cases)

### 1. **虛擬追蹤路徑 (Virtual Traceroute)**

* **情境**：工程師無法直接連線設備執行 `traceroute`，或中間設備阻擋了 ICMP 封包。
* **應用**：透過此工具輸入現有的路由表，即可「在離線狀態下」預測封包會經過哪些交換器，診斷是否在某個節點因為路由遺失而導致斷線。

### 2. **等價多路徑 (ECMP) 驗證**

* **情境**：在資料中心架構中，封包理應平衡分散在多條鏈路上。
* **應用**：分析器可以顯示出一個目標 IP 的所有合法轉發路徑，確認 ECMP 是否如預期設定，或是有某條路徑意外走到了頻寬較小的備援線路。

### 3. **異地備援 (DR) 切換演練**

* **情境**：規劃機房切換時，需要確認流量是否會正確導向備援中心。
* **應用**：修改工具內的路由權重或模擬某節點失效，觀察路徑分析結果是否會自動切換至備援路徑。

### 4. **防火牆策略與路由一致性檢查**

* **情境**：明明路由通了，封包卻沒抵達目的地。
* **應用**：結合拓樸與路由分析，工程師可以快速定位出封包「邏輯上」應該經過哪台防火牆，進而縮小查修範圍至特定的安全性策略 (Security Policy)。
